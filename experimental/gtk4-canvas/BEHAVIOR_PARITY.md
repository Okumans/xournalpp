# Behavior parity ledger

The existing application is the behavior reference. UI modernization must not
silently replace its tool semantics. This experiment is not yet a drop-in GTK 4
version of Xournal++. The initial source inspection was commit `83c0deb9b`;
the current upstream audit target is `b2ef6316989d379cfcb6e1048363a0b6c2befa6b`.

## Known differences that block application replacement

- Shift line/aspect constraints and the main stabilizer families are migrated,
  but draw-direction modifier inversion, drawing and selection-resize grid snapping, Shift-click stroke
  connection, the original inertia/cusp edge cases, and device-specific button
  mappings (`buttonConfig`, `deviceClasses`) still differ or remain absent.
- Shape recognition is a geometric subset: it does not port the original
  segment queue/inertia model, all recognition scores, or snap-to-grid result
  placement. Geometric tools output stroke paths rather than native rectangle,
  ellipse, or arrow model objects.
- The original uses its document, selection, layer, undo, and rich-text models.
  When opening a `.xopp` via the worker, supported round-cap,
  unfilled, undashed, non-audio `pen`, `highlighter`, and `#ffffffff` `eraser`
  strokes plus valid non-empty native text are extracted from the contiguous
  editable suffix of every foreground layer, including hidden layers. Stroke
  pressure sentinels are normalized into positive
  per-point multipliers. Text retains UTF-8 content, supported style runs, and
  its transform. Both are removed from the native snapshot and written back in
  their original layer groups and order, avoiding duplicate objects. Objects
  preceding a non-editable suffix element, unsupported stroke types, audio-linked
  text, and images outside the supported suffix remain visible in per-layer
  previews but cannot yet be edited. Native LaTeX objects in the supported suffix
  retain their editable source and vector PDF, and can be inserted or edited with
  the GTK4 LaTeX tool. Formula replacement and native text-to-formula conversion
  use undoable edits. Layer visibility, selection, add/delete,
  duplicate, rename, reorder, and merge-down are supported. The master layer
  model has no per-layer lock action to port. Visible-layer rectangle and lasso
  selection choose editable strokes, text, and images from the topmost visible
  layer with matches; unsupported objects are not included in that selection
  path.
  Text can be created, edited, selected, moved, resized, rotated, deleted, and
  transferred across pages. The inline editor does not yet follow text transforms.
- The prototype renders a continuous single-column vertical multi-page layout
  and preserves zoom across page navigation, but horizontal, paired-page, and
  multi-column grid layout modes (`LayoutSettings`), scroll-position history
  stacks, and undo/redo for page insertion/deletion are not yet migrated.
- PDF text selection now uses the original PDF source for linear/rectangular
  selection and word/line clicks, and supports copy plus highlight, underline,
  and strikethrough. The action popover still differs from GTK 3's floating
  toolbox in exact placement and dismissal/reopen behavior.
- Relevant `settings.xml` preferences and `.gpl` palettes are imported read-only;
  supported edits are stored in the GTK 4 `gtk4-canvas.ini` overlay. Per-device
  `deviceClasses` mapping and `toolbar.ini` layout customization remain unmigrated.
- The normal application can configure touch behavior, hand recognition,
  scrolling, and gesture zoom. The experiment has only a small input subset.
- Play Object playback works for extracted audio, but the GTK 4 prototype does
  not yet port audio recording, device selection, gain/sample-rate settings, or
  prove that an audio recording remains portable after reopening a saved
  document in a later session.
- The original stroke renderer handles pressure geometry, caps, line styles,
  fill, and blend modes beyond the experiment's simple Cairo segments.
- Remaining work includes other clipboard formats and native object types, IME, plugins, accessibility, platform behavior, and release packaging.
- The input adapter preserves core sequence behavior but uses a compact cubic
  spline path and a single mouse/stylus owner category. It does not yet reuse
  production device-ID routing, the full stroke handler, or exact eraser and
  stabilizer finalization geometry.

The user reports that touchpad scrolling in the current GTK 4 build still moves
too quickly and jumps unpredictably. Reproduce and tune it later on the user's
physical touchpad; the existing synthetic scroll-unit check does not cover this.

Each subsequent migration change should identify its source behavior, add a
regression check, and update this ledger. Passing synthetic input checks is not
evidence of physical pen, touchscreen, or touchpad parity.

## Save and autosave publication limits

Save compares content versions for the primary file and attached PDF/pixmap
sidecars before overwriting, and checks again during publication. It cannot make
multiple filesystem paths atomic against unrelated external writers. Save uses
a private staging directory, publishes the document last, and preserves recovery
copies if attachment rollback is unsafe. The tests inject failures before commit;
they do not simulate power loss. An existing `filename~` is not overwritten.

Background autosaves stage into the target directory and replace `.name.autosave.xopp`
or `<cache>/xournalpp/autosaves/<pid>.autosave.xopp` via `.swap` without modifying the
primary saved document or its `~` backup. Opening a recovery artifact never marks the
recovery path itself as a direct `Ctrl+S` target: sidecar recovery re-associates the
saved `.xopp` while keeping the session dirty until saved, and startup recovery leaves
the document unnamed (`Save As`) and adopts a current-PID cache autosave before removing
the recovered artifact. Unlike GTK 3 `CrashHandler`, the prototype does not write
`emergencysave.xopp` from an async-signal handler; uncatchable crashes (`SIGKILL`)
recover up to the latest completed autosave, and orphaned cache detection uses POSIX
`kill(pid, 0)` liveness checks. Interactive settings persistence and platform-specific
file semantics remain migration work.

## Selection scope

Rectangle and lasso selection apply to editable standard strokes, text, and images in the active visible foreground layer. Their visible-layer variants search foreground layers from top to bottom, skip hidden layers, and select all matching objects from the first visible layer with matches, matching `Selector::finalize()`; they do not combine selections from several layers. Rectangular objects use transformed four-corner containment like `RectangularElement::isInSelection`. Select Object selects the closest editable stroke, text, or image within 0.5 document points on the active visible layer; exact overlapping hits prefer the frontmost object, and Shift adds an object to the current selection. Smart Select picks the topmost editable stroke, text, or image for drag movement; a text click still opens the inline editor. The Text tool also supports dragging text to move it and dragging its handles to resize or rotate. Finishing text creation or editing leaves the item selected. Mixed selections share move, resize, rotate, delete, cross-page transfer, and clipboard operations. The bounded `application/xournal` clipboard codec supports ordered pen, highlighter, whiteout, text/link, raster image, and LaTeX image groups; copy offers rendered PNG/SVG and plain text when applicable. Cut, duplicate, paste, and undo preserve the group as one edit. Unsupported native object records are rejected atomically.

Stroke move, side/corner resize, mirroring, rotation and cross-page transfer preserve pressure/style and commit as one undoable edit. Moves snap the nearest selection corner to the destination page grid, with the legacy tolerance and Alt override. Resize handles snap their moving edge axes, and move drags pan at the configured edge rate while the pointer remains stationary. After a committed rotation, the visible frame stays axis-aligned; subsequent resize uses the accumulated selection rotation for its scale axes. Undo and redo restore the frame and rotation state with the object geometry. Text and images share selection handles and commit mixed transforms and deletion as single undoable edits. Text can also be moved and transformed directly with the Text tool; toolbar font, size, style, and color changes participate in undo history. Images support move, aspect-preserving corner resize, center-anchored rotation with legacy snapping tolerance, and native clipboard transfer. Preview geometry is separate from the committed autosave snapshot. Cross-page strokes, text, and images append above existing destination objects. Finite stroke points outside page bounds remain editable and round-trip through the native document worker, matching transform freedom in the original model. The text editor does not follow transformed text. Unsupported native objects cannot be selected or edited; unsupported clipboard records are rejected atomically. Physical input and cross-process clipboard exchange remain unverified.
